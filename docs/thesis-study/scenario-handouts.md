# Scenario Handouts (Domain Packs with A/B Variants)

Use one variant per condition run.
Counterbalance by order so half of groups see A then B, and half see B then A.

## Key Clarification: AI-light Is a Condition, Not a Scenario

`AI-light` is not a separate task prompt.
It is the same scenario run with reduced AI autonomy/proactivity settings.

For valid comparison, keep scenario content constant and only change condition settings.

## How to Use Domain Packs

1. Pick one domain pack for a group.
2. Use variant A and B from the same pack across the two condition runs.
3. Keep timing, facilitator prompts, and deliverable rubric identical across both runs.

## Common Instructions for Participants

- Complete all work inside the app.
- Do not use external chat tools during the session.
- You may use AI features available in the current condition.
- Focus on delivering a usable team plan, not perfect wording.

## Required Outputs in Every Run

1. A clear project plan summary in chat or insight content.
2. Three key tasks with owner and target date.
3. At least one accepted action item.
4. At least one dismissed action item.
5. At least one completed action item by session end.
6. One verified decision traced back to source context (chat marker and linked insight).

## Required Interaction Checkpoints in Every Run

1. Update task context at least once.
2. Use Ask flow at least once.
3. Use Research flow at least once.
4. Perform at least one marker/insight jump for traceability verification.

## Domain Pack 1: Software and Product (Baseline)

## Variant A: Student Hackathon Launch Plan

### Context

Your team is preparing a campus hackathon support app for launch.
The app helps teams find members, manage tasks, and generate AI summaries.
A demo is due in 2 weeks.

### Team Objective

Create a realistic launch execution plan for the demo milestone.

### Constraints

- Team has limited time: 2 weeks.
- Only 3 team members are available.
- Budget is limited to free-tier tools.

### Tasks to Decide

1. Feature scope for demo (must include 3 core features).
2. Division of responsibilities across team members.
3. Validation plan (how you test readiness before demo day).

### Mid-Run Change Injection (Facilitator at minute 8)

A key teammate is unavailable for 3 days before demo.
Re-prioritize your plan while still keeping demo scope viable.

### Deliverable Format

- Final plan paragraph.
- Top 3 tasks with owner and target date.
- One sentence rationale for final scope choice.
