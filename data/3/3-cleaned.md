**Participants:** Aung (P1), Shanyl (P2, male)
**Structure:** Solo AI-on → Team AI-on → Team AI-light
**Scenarios:** Creative project concept (solo), Divergent
creative project reconciliation (team AI-on), Trip planning
with shortened trip constraint (team AI-light)
**Survey instrument:** Final version.
**Note on data quality:** Good coverage for both participants.

interaction bug present: reply and help features cancelled
each other out; consistent behaviour only observed for
auto, Ask Assistant, and Research modes. Research mode
prompt rigidity continues from Session 2. Shanyl is male.

conceptualisations as the team AI-on convergence task
was an ambitious framing. The AI's tendency toward

design observation in the methodology write-up.

introduced but not meaningfully incorporated by the AI,
raising a question about resolution quality under
reduced-capability conditions that is analytically
relevant to AQ4.

## Phase 3 — Team AI-Light (Trip Planning, Shortened
Trip Constraint)

**Constraint:** Trip to be shortened — introduced
mid-session. AI did not meaningfully engage with or
incorporate this constraint under AI-light conditions.
Resolution of the disagreement this generated was
partial — mostly resolved through participant
negotiation rather than AI-mediated convergence.
This is a resolution quality finding: AI-light
completes tasks at surface level but lacks contextual
reasoning capacity for mid-session constraint handling.

**Feature suggestions raised during this phase:**
- Two-button mode switching — clearer toggle between
  AI-on and AI-light. [Feature suggestion, not
  observation of existing UI.]
- Visibility of context updates — display context
  changes similarly to group chat name changes.
  Framed explicitly in terms of traceability:
  context changes affect decision-making and should
  be visible to all participants in real time.

### Shanyl
- Not much difference in outcome between AI-on
  and AI-light for this task — process was more
  straightforward under AI-light.
- Research and summary may be useful for higher-level
  projects but currently lack precision for
  specific tasks.

### Aung
- Would use both AI-on and AI-light in tandem —
  sees them as having varying degrees of usefulness
  for different tasks, and would reference different
  components depending on need.

## Analytical Flags — Mapped to AQ Framework

**AQ1 — AI Routing Behaviour**
The rough idea Q4 result for both participants is the
primary AQ1 finding. Research mode prompt rigidity
prevented either participant from developing confident
mode-appropriate use — routing behaviour was shaped
by which features worked reliably rather than by
deliberate mode-matching. Aung's use of reply as a
context-specificity mechanism is a notable creative
workaround — using a feature outside its primary
intent to achieve what Ask mode could not. Shanyl's
default to Ask Assistant as the best available option
is consistent with Session 2. Across sessions 2 and
3, Ask Assistant is emerging as the de facto primary
mode not because it is the most appropriate for all
tasks but because it is the most consistently
functional.

**AQ2 — Traceability and Trust**
Shanyl's traceability-by-scrolling behaviour is the
primary AQ2 observation — chat history is more
naturally discoverable as a provenance mechanism than
the traceability UI for this participant. The
reply-context bug is directly relevant: suggestions
surfacing from incorrect reply context mean provenance
is not just hard to find but actively misleading in
some instances. Aung's high pre-session provenance
priority against a rough idea mode clarity exit score
is the clearest expectation-gap data point for AQ2
in the study — he entered caring most about source
attribution and exited with the least clarity about
it.

**AQ3 — Shared Understanding**
Shanyl engaged with the context panel immediately
in the solo phase — the fastest unprompted context
engagement in the study. In the team phase, context
incorporation was valued in principle but actionable
items failed to translate context changes into
concrete shared tasks. The participant-generated
suggestion of displaying context updates like group
chat name changes is a direct design proposal for
improving AQ3 discoverability — unprompted
identification of the same gap the research package
had diagnosed.

**AQ4 — Coordination Support**
Team AI-on with divergent creative conceptualisations
produced limited convergence — the AI's facilitative
outputs were too general to resolve genuine creative
disagreement. This extends the Session 2 finding:
AI keeps groups loosely coordinated but does not
drive convergence on substantive disagreements,
and this limitation is more exposed when the
disagreement is conceptual rather than
preference-based. The AI-light constraint failure
is an important AQ4 finding: resolution quality
degrades under AI-light in a way that task
completion rates alone would not reveal.
Aung's proposed tandem use of both modes is the
most pragmatic user-generated coordination strategy
observed in the study.

**AQ5 — Contextual Catch-Up**
Shanyl independently identified summary as a
catch-up mechanism for new joiners — unprompted
and directly relevant to AQ5. No formal new joiner
scenario was run in this session, but this
participant-generated observation strengthens
the case for summary as the primary AQ5 artifact
across the study.
